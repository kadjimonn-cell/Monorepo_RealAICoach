# Global Investigation: PDF v1.4 Theme/Layout Compliance Gap

Date: 2026-04-27
Owner: E1
Status: OPEN (RCA complete; remediation pending approval)

## Trigger
User reported that PDF attachment appears unbranded/plain while email body is v7-branded.

## Scope Audited
- PDF policy middleware (`middleware_pdf_policy.py`)
- Interview performance PDF flow (`routes/interview_experience.py`)
- Email template system (`utils/email_templates.py`, `utils/email_service.py`)
- Platform-wide PDF generators (payments, offers, content, miniapps, mock interview, careers, etc.)

## Evidence-Based Root Cause (System-Level)
### Verified facts (no assumptions)
1. `middleware_pdf_policy.py` enforces PDF byte-version policy (`%PDF-1.4`) and response headers only.
   - It does not parse/validate branding/theme tokens.

2. `routes/interview_experience.py` currently renders attachment PDF with direct ReportLab primitives:
   - `canvas.Canvas(..., pdfVersion=(1,4))`
   - plain `Helvetica`/`Helvetica-Bold`
   - direct `drawString(...)` blocks
   - no v7 email-style branding primitives/logo shell integration.

3. Email body for this flow is v7-branded template:
   - `send_catalog_template(... template_key="employer_notification_v7", attachments=[...])`
   - confirms body and attachment are generated by different rendering stacks.

4. Platform scan confirms mixed PDF generation patterns across multiple modules.
   - Branded utility exists (`utils/receipt_generator.py`) and is used in payments paths.
   - Separate direct PDF builders also exist in other route files.

## Evidence
- User-facing issue reproduced visually: plain interview performance PDF attached to branded v7 email.
- New interview performance renderer generates valid v1.4 PDF but minimal/plain layout by design.
- Global code scan confirms many independent PDF renderers across the platform.

## Impact
- Inconsistent enterprise brand presentation across attachments.
- Perceived compliance gap despite technically valid PDF version policy.

## Immediate Remediation Plan (Proposed)
1. Introduce/extend centralized branded PDF template utility for interview performance summaries.
2. Refactor interview performance PDF generator to use platform-approved branded PDF shell.
3. Add CI gate: disallow new direct route-level PDF renderers unless allowlisted.
4. Add branding-compliance tests for attachment flows (in addition to v1.4 checks).

## Files with concrete findings
- `backend/routes/interview_experience.py` (plain direct ReportLab rendering for interview attachment PDF)
- `backend/routes/payments.py` (delegates to `utils/receipt_generator.py` branded utility)
- `backend/utils/receipt_generator.py` (central branded PDF engine exists)
- `backend/middleware_pdf_policy.py` (version policy only)

## Acceptance Criteria for Closure
- PDF attachment retains `%PDF-1.4` header.
- Visual match with enterprise brand tokens (header/footer/logo/section hierarchy) verified.
- Regression tests pass for version + branding checks.
